# PRD 体检与决策台账

## 八类产品输入

已有 PRD 直接复用；没有时围绕以下字段访谈，不强迫产品负责人先写技术规格：

| 字段 | 要明确的内容 |
| --- | --- |
| 目标用户与核心任务 | 谁在什么场景完成什么任务 |
| 输入、过程与产物 | 用户提供什么、途中需看/确认什么、最终得到什么、保留什么 |
| Agent 主链路 | 一次生成、多轮对话、分步确认还是动态工具调用；人工确认点 |
| 效果标准 | 好结果长什么样、可接受瑕疵、谁判断；缺数字可待样例评分 |
| 阶段与优先级 | 最小闭环、后做项、截止约束；已批准范围优先 |
| 模型与成本 | 指定/禁用厂商、单次或周期预算、已有配置 |
| 数据与非功能 | 隐私、敏感信息、留存、用户量、时延、文件约束及数据地域 |
| 交付与账号 | 本地自用、内部试用或对外；登录、部署预算及已有平台 |

每项区分已确认、待确认与假设。不把示例用户、阈值和预算复制成真实要求。

## 补全清单

先查缺失、含糊和矛盾，再分类：

- **必须问**：改变用户、核心任务、费用、安全、隐私或范围的缺口。每轮最多 5 个，用问题 / 选项 / 推荐 / 不选的后果表达。
- **可默认**：不触及上述关键边界的实现细节。写默认建议及理由，不能把数据留存或敏感数据上传当成无需确认的小事。
- **待样例评分**：效果标准还需真实样例，由用户判断后形成项目尺度。允许带显式待验项推进原型，但不算通过真实验收。

用户回答后更新清单并将决定落入台账。已有决定不重复问；新输入冲突时只复核受影响部分。第 0 阶段的阻断项关闭或明确约定后续验证方式，才进入技术适配。

## 状态文件模板

工作台使用项目根目录的 `项目状态.md`，不要求创建原项目的 docs/ 目录。当前已有状态文件时沿用，不覆盖内容。

```markdown
# 项目状态

## 当前阶段
- 阶段：
- 最近更新：
- 上次停在：
- 本次范围：
- 下一步：

## 决策台账
| 编号 | 决策 | 已定 / 待定 / 待验证 | 结论 | 依据 |
| --- | --- | --- | --- | --- |

## 待确认问题
- 问题 / 选项 / 推荐 / 后果

## 验证记录
| 要求 | 真实证据 | 结果 | 未覆盖范围 |
| --- | --- | --- | --- |

## 阶段历史
- 日期、已完成范围、验收记录位置、保留风险
```

决策台账聚焦当前阶段，通常不超过 10 个活跃条目；长期决定仍需保留在已有记录中，不为限额删除历史。可涵盖任务、效果标准、瑕疵容忍、模型/预算、登录、留存、隐私、确认动作及交付环境。状态是项目进展，不代表工作台启动时要恢复页面。

密钥、AccessKey、密码、邀请码和敏感原文不进入此文件。只记安全配置位置、非敏感状态及授权范围。记录是修改候选，界面确认后才算已保存。
