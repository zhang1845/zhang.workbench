# 部署准备、执行与收尾

## 是否需要部署

用户只要求本地使用、打包 App、上传代码或打 Git 标签，不等于同意上线。只做上线咨询时交付方案。实际部署需用户明确要求，并确认目标平台、账号、环境、数据和授权范围；创建计费资源前说明费用量级、计费方式及预算并等待同意。

原手册以火山引擎 veFaaS 等服务为示例，这不是本技能的强制路线。已有平台优先复用；不默认要求企业认证、开全权限、安装 CLI 或迁移数据库。选择平台后查官方现行文档，核验支持的运行时、认证、权限、命令和价格，不复用未经核实的旧命令或费用。

## 上线方案摘要

用产品语言说明当前本地验收是否通过、要发布什么、给谁访问、会上传哪些资料、何处存数据/文件、登录方式、服务费用依据、运行和回滚方式。费用无法核实就标未知，不许编报价。

列出需本人操作的事项，给出“去哪、点什么、填什么、看到什么算对”；不要求把密钥贴入聊天。采用受保护的 Secret 或安全配置，最小权限且限于目标资源。删除/降权凭据由用户确认，不越权自行清理。

## 发布前后检查

1. 构建包不含 .env、真实数据、凭据、调试输出等敏感材料；前端只包含可公开配置。
2. 生产配置与构建期配置区别明确；后端地址、代理、HTTPS 与流式代理链实际验证，不把部署成功的退出码等同用户可用。
3. 数据与长任务有持久化、备份和实际恢复验证；临时磁盘、常驻实例或内存不能被描述成持久数据库的保证。
4. 对外或多用户环境验证后端鉴权、未登录拒绝、A 无法读写 B 的数据；不能只隐藏前端按钮。
5. 文件资产按业务归属受控读写；大文件和元数据分开管理，不能泄露访问地址或越权下载。
6. 核心输入 → 模型/业务处理 → 产物 → 再登录/刷新取回完整走通；对有移动或跨设备要求的产品增加对应实测。
7. 记录可追踪请求的日志和错误告警，不暴露秘密、堆栈或完整用户资料；检查失败与回滚路径。

任一步未获授权、能力不足或验证失败，停止相应外部动作并报告；仍可补充本地方案。不存在“加载这个技能就可自动上线”的权限。

## 收尾

交付实际可访问地址、登录与操作说明、[闸门及证据](gates.md)、未解决风险和回退办法；更新项目状态与启动/验证说明。不得捏造 URL、截图或验收结果。

提醒用户撤销或降权临时部署凭据；未收到反馈只能记已提醒。提交、推送仓库、发 Release 或删除资源均需要对应用户授权，不作为部署后的自动步骤。
