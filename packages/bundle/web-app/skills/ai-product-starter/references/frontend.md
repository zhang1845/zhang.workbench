# 前端交付与可恢复交互

## 进入条件和范围

复用已确认设计、现有组件和主题系统。核心链路尚不确定时优先最小验收界面；如果交互本身决定任务能否完成，则用纵向切片，不硬等所有后端结束。一次聚焦已选主要终端，不默认扩到 Web、手机和桌面全部平台。

先交代输入材料、目标用户任务、页面/产物、技术适配、接口/状态、响应式目标、风险及本阶段验收。用户只请求 UI 修改时保留既有业务和技术，不附加重新选型。

## 真实任务状态

在前端适配层对应后端已有语义：未开始、提交中、排队、执行中、流式、待用户、成功、部分成功、失败、取消、断连或过期。只使用本产品存在的状态，不把表格变成必须全部实现的枚举。未知状态显示安全兜底，不当成成功。

每个关键状态说明现在发生什么、用户要做什么、下一步是什么。加载、空数据、失败、无权限与不存在分开；接口没返回前不闪“暂无数据”。失败时保留输入和中间产物，不清空页面。

人工确认展示已完成内容、待决定项、影响、撤销或放弃方式。按钮写具体动作，不用含糊的继续掩盖费用或不可逆后果。

## 提交、断线与恢复

- 重复点击不能创建多份付费任务；提交状态与后端幂等配合。超时先查原任务，不盲目重建。
- 断线不等于任务停止。按任务 ID 查询实际状态，恢复中间产物与必要连接，避免重复追加流内容。
- 浏览器停止等待与服务端取消任务分别表达；没有后端取消能力不能把按钮写成已取消任务。
- 结束、切换、卸载时释放流或轮询；查询有间隔和退避，不多组件重复高频轮询。
- 用户正在向上读历史时不强制滚到底部；内部日志和用户产物分层，不显示秘密或敏感推理材料。

这些是任务恢复要求，不要求改变工作台每次启动进入首页的行为。

## 代表页验收

先看一个代表性任务页面，再扩展同类页面。检查加载/空/错/禁用/成功、确认对话框、菜单遮挡、滚动、键盘焦点、目标宽度下布局；按现有主题检查文字可读性。涉及语音/媒体才检查权限、格式探测、播放清理与目标设备，不强加无关功能。

在允许执行的工程中运行相关类型检查、Lint、构建及关键交互测试，再真实操作核心闭环：进入 → 输入 → 提交 → 查看运行 → 用户确认 → 产物 → 刷新后查回任务。生产构建不代替页面预览；宽度模拟不冒充真机测试。

截图、地址或操作步骤、[阶段闸门](gates.md)构成用户可核对的证据。截图工具或真机不可用时如实标注缺少的复核，不能把 DOM 检查称为外观截图验收。
