# AI 产品分阶段交付

面向已有产品方向的工程交付，不替用户决定是否值得立项。用产品语言说明当前阶段、推荐取舍和下一步；不要求用户先设计数据库或选择一串框架。

## 启动与接续

先读当前项目规则、PRD、阶段文档、已有状态和用户本轮请求。只有概览或咨询请求时先答对应问题，不启动整个开发流程。有明确交付请求时，从现有进展继续，不让已完成的项目重走全部阶段。

没有 PRD 时按[PRD 与决策台账](references/prd-and-state.md)访谈；每轮最多 5 个会改变用户、任务、成本、安全、隐私或范围的关键问题，附推荐及后果。其余采用有依据的默认值，请用户确认，不假装缺口已消失。效果标准说不出数字时记待样例评分，不替用户编验收线。

## 只推进当前阶段

| 阶段 | 要交付什么 | 按需读取 |
| --- | --- | --- |
| 0 PRD 体检 | 补全清单、已确认要求与未决问题 | [PRD 与决策台账](references/prd-and-state.md) |
| 1 技术适配 | 单一推荐、依据、暂缓项与影响 | [技术适配与验证](references/engineering.md) |
| 2 MVP | 最小核心链路、验证计划与实际证据 | [技术适配与验证](references/engineering.md) |
| 3 正式前端 | 目标终端、任务状态与恢复交互、代表页验收 | [前端交付](references/frontend.md) |
| 4 部署准备 / 执行 | 部署方案、费用与数据安全检查；获授权才执行 | [部署与收尾](references/deployment.md) |
| 5 收尾 | 状态、启动/验证说明、风险与密钥降权提醒 | [部署与收尾](references/deployment.md) |

各阶段均用[阶段闸门](references/gates.md)记录通过、未通过、待验或不适用及依据。未通过不能宣布该阶段完成；不适用说明原因。技术声明和需求阶段不要求运行不存在的代码；涉及模型能力的验收不能用 mock 冒充真实调用。没有 Key 或无执行环境时交付当前可做的文档，并保留待验项。

## 保留产品与执行边界

沿用用户已有技术栈、模型配置、认证和部署环境，不强制迁移 Python、Next.js、火山引擎或某个模型。默认后端核心先验证；人工确认、画布或媒体交互本身就是核心时，做最小纵向切片。用户只要本地使用时，部署阶段记不适用，不擅自上线。

技能不赋予部署、付费、发消息、注册账户、提交仓库或删除秘密的授权。需要外部平台操作时先确认对象、范围、数据上传与费用。密钥通过产品安全配置或平台 Secret 录入，不要求贴进聊天，不写入仓库、前端、报告或截图。

## 工作台中的文档操作

这是当前工作台内的交付方法，不是另一套开发运行时。文档项目仅允许当前项目根目录内独立的 Markdown 或文本文件；采用 `PRD.md`、`项目状态.md`、`技术适配声明.md`、`阶段2-验收.md` 等现有或新文件名，通过 read / write / edit 提交预览，确认后才算保存。原项目的 docs/ 子目录布局不是这里的强制要求。

工作台限制代码执行时，交付方案、开发交接与验收清单，明确尚未实现或验证，不绕过审阅用 shell、脚本或其他工具写文件。用户另行授权在可执行工程中开发时，才按那个工程的规则执行；不覆盖用户原文件、测试或数据，不把“加载技能”当作启动后续阶段的许可。仅讨论时不写文件。
