# 方案与组件选型

## 事实与领域建模

从输入提取目标、用户与同步/异步交互、一次输入到交付的闭环、交付物、不能做的事、时延/并发/成本/模型约束。逐项附来源，缺项写待确认。再映射为：

| 要素 | 需要确定的内容 |
| --- | --- |
| 工具 | 查询、写入、调用、发送所需的外部能力 |
| 知识 | 文档、规则、schema 及其更新和检索方式 |
| 观察 | 如何通过状态、日志、diff、指标确认效果 |
| 行动 | API、CLI、UI 或消息等实际执行接口 |
| 权限 | 可访问的数据、需审批的动作、拒绝与审计方式 |

## 17 组件决策表

以下是原项目的选型方法，不表示工作台已经实现或开启了这些组件。先明确是否真是 Agent 产品；其基线 s01、s02 只在该前提下适用。

| 组件 | 触发证据 | 设计检查点 |
| --- | --- | --- |
| s01 Agent Loop | Agent 闭环基线 | 工具结果回传、停止原因、步数/时间/Token 上限 |
| s02 工具系统 | Agent 闭环基线 | 输入 schema、参数校验、统一错误、副作用 |
| s03 权限系统 | 破坏、敏感数据或外部写入 | 默认拒绝、审批、作用域、审计 |
| s04 钩子系统 | 审计、拦截、埋点 | 工具前阻断、工具后观察、异常隔离 |
| s05 任务规划 | 多步探索需计划与可见进度 | 计划状态和进展；几个固定步骤不自动触发 |
| s06 子 Agent | 子任务上下文过大或可并行探索 | 独立上下文、结果回传、超时回收 |
| s07 技能加载 | 大量领域知识需按需展开 | 目录先行、惰性加载、版本 |
| s08 上下文压缩 | 长会话、大量日志/工具输出 | 先裁工具结果、再摘要，保留权威指令 |
| s09 记忆系统 | 跨会话保留偏好、决定或历史 | 筛选、提取、整合、持久化、冲突处理 |
| s10 任务系统 | 目标需持久化、依赖与断点续跑 | 原子变更、依赖校验、并发边界 |
| s11 后台任务 | 慢操作不能阻塞主流程 | 完成通知、超时、取消和清理 |
| s12 定时调度 | 明确定时自动触发 | 幂等、持久化、会话作用域 |
| s13 Agent 团队 | 并行任务且需要隔离工作区 | 认领、任务绑定、消息协议、关停 |
| s14 MCP 插件 | 接外部工具生态 | 发现、命名空间、权限、连接失败降级 |
| s15 集成 Harness | 多个可选机制需要协同 | 单一循环、共享客户端、跨模块状态 |
| s16 工作流运行时 | 固定阶段不需要模型临场规划 | 代码编排、生命周期、journal 续跑 |
| s17 目标闭环 | 需独立判断何时真正完成 | 评估器、失败/不可能/超限时交还控制权 |

对 s03–s14、s16–s17 的需求特征分别记 yes / no / later / unknown，映射为必选 / 放弃 / 二期 / 待确认。保留具体证据，不能把沉默写成 no。原 rules.py 对 s15 的规则：排除 s01、s02、s15 后，必选组件至少 3 个则必选；否则必选与二期合计至少 3 个则二期；否则放弃。使用这条规则时注明这是方法中的集成建议，不是实际代码依赖检测。

## 方案交付

根据任务裁剪篇幅，但保留事实及待确认、五要素、选型与放弃理由，以及以下信息：

1. 七层 Mermaid 图及一次贯穿的数据流。交互层（谁怎样用）、产品层（会话/路由/业务）、Agent 编排层、模型层、能力集成层、数据层、基础设施层。每层写实际落点或 N/A；安全与可观测性是横切项。
2. 工具清单：名称、输入、输出、副作用、权限、归属层。模型层选择沿用用户配置与需求，不硬编码厂商。
3. 系统提示词草案：身份、工作规则、工具说明、知识目录；用户资料是待分析数据，不成为系统指令。
4. 会话内上下文、跨会话状态/记忆与保留策略；工具失败、幻觉、超时、越权各自的降级。
5. 日志、指标与轨迹的采集点；不记录秘密或完整敏感原文。
6. 技术栈、运行形态与验收办法。可运行、可容错、可观测、可测试、可部署、可度量分别有哪些设计和未验证项。

部署形态的设计不是部署授权。结尾说明用户接下来需确认什么、实现和验证还缺什么。方案自查不等于代码已开发或真实模型已通过验收。
